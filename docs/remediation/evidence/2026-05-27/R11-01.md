# Evidence Manifest — R11-01: web_browse_tool skips DNS validation

## Row Metadata
- **Row ID**: R11-01
- **Status**: PARTIAL (deferred — fetcher not wired)

## Problem
R11-01 flags that `agent/web_browse_tool.py` doesn't do DNS resolution — host classification only works for IP literals. DNS rebinding attacks could bypass private-IP checks.

## Investigation
Verified in the source: `agent/web_browse_tool.py` is **a schema/validator-only module**. It defines tool descriptors and URL validators, but deliberately does NOT make HTTP requests (line 5-6: "It deliberately does **not** make real HTTP requests").

Line 92-93: "Hostnames that are not IP literals are only classified as blocked when they appear in the static `_BLOCKED_HOSTNAMES` set — DNS resolution is intentionally not performed here (the module is side-effect free)."

The module is architecturally correct for its role. The **fetcher** (not yet implemented) is where DNS rebinding protection needs to live, using a resolve-then-connect pattern.

## Relation to H-24
- `tools/web_tool.py` is the actual fetcher (used by WebTool) — I did fix H-24 there with redirect re-validation
- `agent/web_browse_tool.py` is just the schema layer — no fetching happens there, so no DNS attack surface currently exists

## Remaining Work
When `agent/web_browse_tool.py` gets an actual fetcher wired up, the fetcher must:
1. Resolve the hostname via socket.getaddrinfo
2. Validate the resolved IP(s) against _PRIVATE_V4_NETS
3. Connect directly to the resolved IP (not the hostname) so rebinding is impossible
4. Apply the same checks at each redirect hop (now implemented for tools/web_tool.py via H-24 fix)

No changes needed today. Evidence: documented design intent in source comments.
