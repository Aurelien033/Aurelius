# Evidence Manifest — C-19: Multiprocessing Tokenize Arity Fix

## Context
- **Task ID**: C-19
- **Title**: Broken multiprocessing in tokenize pipeline
- **Severity**: Critical
- **Theme**: E-Model
- **Primary File**: training_data/tokenize_pipeline.py

## Problem Statement
The `TokenizePipeline.tokenize_texts()` method had incorrect arity when calling `pool.map()`:
```python
all_ids = pool.map(self._tokenize_text, [tokenizer] * len(texts), texts)
```

`pool.map(func, iterable, chunksize)` was called with:
- `iterable` = `[tokenizer] * len(texts)` (list of tokenizer references)
- `chunksize` = `texts` (list of strings, should be int)

This caused `TypeError: '<=' not supported between instances of 'list' and 'int'` when `len(texts) > shard_size`.

## Root Cause Analysis
1. **Primary bug**: Incorrect `pool.map` arity — texts list passed as chunksize parameter
2. **Secondary bug**: Fallback `_SimpleTokenizer` was a nested class, not picklable for multiprocessing

## Changes Applied

### 1. Fixed pool.map → pool.starmap with correct arity
**File**: `training_data/tokenize_pipeline.py:83`

**Before**:
```python
all_ids = pool.map(self._tokenize_text, [tokenizer] * len(texts), texts)
```

**After**:
```python
all_ids = pool.starmap(self._tokenize_text, [(tokenizer, t) for t in texts])
```

### 2. Moved _SimpleTokenizer to module level for pickling
**File**: `training_data/tokenize_pipeline.py:15-28`

Extracted nested class to module level so it can be pickled for multiprocessing:
```python
class _SimpleTokenizer:
    """Fallback tokenizer when tokenizers package not installed. Module-level for pickling."""
    def encode(self, text: str) -> list[int]:
        return [ord(c) for c in text]
    
    @property
    def vocab_size(self) -> int:
        return 128000
```
