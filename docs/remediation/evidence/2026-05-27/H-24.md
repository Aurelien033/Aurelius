# Evidence Manifest — H-24: HTTP redirects not re-validated

## Row Metadata
- **Row ID**: H-24
- **Status**: FIXED

## Problem
`tools/web_tool.py` used `urllib.request.urlopen()` which follows redirects automatically. An SSRF-prone redirect from a public URL to a private IP (e.g., 169.254.169.254 AWS/GCP metadata) would bypass the URL safety check on the initial URL.

## Fix
- Built a `_NoRedirectHandler` that raises HTTPError on 3xx instead of following
- Created a module-level `_opener` using this handler
- `fetch()` now manually follows redirects up to `_MAX_REDIRECTS` (5), re-running `_is_safe_url()` at each hop
- Rejects redirect chains targeting private IPs
- Added redirect-loop guard

## Tests Added
- `test_fetch_rejects_redirect_to_private_ip`: public → metadata service, hop 2 rejected
- `test_fetch_follows_safe_redirect`: public → public is followed
- `test_fetch_rejects_redirect_loop`: infinite redirect terminated at _MAX_REDIRECTS
