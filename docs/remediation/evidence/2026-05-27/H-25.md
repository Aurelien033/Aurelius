# Evidence Manifest — H-25 / R10-01: BFF Database Persistence

## Status: FIXED

## Problem
BFF route state (users, BFF agents, files metadata, traces, scheduler tasks, chat conversations) lived in in-memory `Map`s and was lost on restart. Alembic schema existed but was unused by `middle/`.

## Solution

### SQLite persistence layer (`middle/src/store/`)
- `MemoryBffStore` — used when `MIDDLE_DATABASE_URL` is unset (ephemeral dev mode)
- `SqliteBffStore` — used when `MIDDLE_DATABASE_URL` is set (`sqlite:./data/middle.sqlite` or path)

### Wired routes
| Route module | Persisted entities |
|--------------|-------------------|
| `auth.ts` | users, sessions |
| `agents.ts` | BFF agent registry (SSE subscribers remain in-memory) |
| `files.ts` | file metadata + user quota (bytes on disk under `UPLOAD_DIR`) |
| `traces.ts` | agent traces + steps |
| `scheduler.ts` | cron tasks (restored on boot via `restoreSchedulerTasks()`) |
| `chat.ts` | conversations |

### Data engine snapshot
- `MIDDLE_ENGINE_DATA_PATH` (default `./data/bff-engine.json`) — `loadFromFile` on boot, `saveToFile` on graceful shutdown when not ephemeral

### Configuration
```bash
export MIDDLE_DATABASE_URL=sqlite:./data/middle.sqlite
export MIDDLE_ENGINE_DATA_PATH=./data/bff-engine.json
# Optional: force ephemeral even with URL unset
# export MIDDLE_EPHEMERAL_MODE=true
```

### Health / UI
- `GET /health` → `persistence: database`, `ephemeralMode: false` when configured
- Frontend header banner only when `ephemeralMode: true`

## Residual
- PostgreSQL URL support not implemented (use SQLite file or add `pg` adapter later)
- Alembic `0001` Python tables are separate from BFF SQLite schema (intentional for this pass)
- Full sync between DataEngine and SQL `agents` table deferred
