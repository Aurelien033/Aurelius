# Evidence Manifest — C-15: Voyager Skill Library Exec Gate

## Context
- **Task ID**: C-15
- **Title**: Arbitrary code execution in Voyager skill verification
- **Severity**: Critical
- **Theme**: T5 Sandbox exploit locks
- **Primary Files**:
  - `agent/skill_library.py`
  - `src/agent/skill_library.py`

## Problem Statement
`VoyagerSkillLibrary.verify_skill()` and `_run_test_case()` executed stored skill code and assertion strings with raw `exec()`.

That means any persisted or supplied skill body could run arbitrary Python during verification. This is not a subtle bug; it is literally an interpreter-shaped footgun.

## Root Cause Analysis
1. **Default-open execution**: skill verification executed code without an explicit environment gate.
2. **Duplicate import surfaces**: both `agent.skill_library` and `src.agent.skill_library` exist and can be imported directly, so fixing only one leaves an exploitable twin.
3. **Import-time gate hazard**: an environment gate computed at module import time ignores later `monkeypatch.setenv()` / runtime configuration changes. The gate must be checked at call time.
4. **No suspicious-pattern filter**: enabled execution had no defense against common escape patterns like `__import__`, `eval`, `exec`, `open`, subprocess, socket, pickle/yaml unsafe loads, and obvious filesystem mutations.

## Changes Applied

### 1. Added call-time execution gate
**Files**:
- `agent/skill_library.py`
- `src/agent/skill_library.py`

Added `_skill_exec_allowed()`:
```python
_SKILL_EXEC_ENV = "AURELIUS_ALLOW_SKILL_EXEC"


def _skill_exec_allowed() -> bool:
    return os.environ.get(_SKILL_EXEC_ENV, "0") == "1"
```

Skill code execution is now disabled by default. It only runs when `AURELIUS_ALLOW_SKILL_EXEC=1` is present at the time of verification.

### 2. Routed every exec path through `_safe_exec()`
**Files**:
- `agent/skill_library.py`
- `src/agent/skill_library.py`

Replaced raw `exec()` calls in:
- `verify_skill(skill.code, ...)`
- `_run_test_case()` string test cases
- `_run_test_case()` dict `setup`
- `_run_test_case()` dict string assertions

### 3. Added suspicious-code filter
**Files**:
- `agent/skill_library.py`
- `src/agent/skill_library.py`

Blocked common ACE / I/O / network / subprocess patterns, including:
- `__import__(...)`
- `eval(...)`, `exec(...)`, `compile(...)`, `open(...)`
- `os.system`, `subprocess.run/call/Popen`
- socket / urllib / mutating requests methods
- pickle/yaml unsafe load surfaces
- obvious `Path(...).write_text/write_bytes/unlink` mutations

### 4. Added regression tests across both import surfaces
**File**: `tests/agent/test_skill_library.py`

Added tests for both `agent.skill_library` and `src.agent.skill_library`:
1. Code execution is blocked by default and does not create a marker file.
2. Safe pure-Python skill verification works when explicitly enabled.
3. Suspicious code is rejected even when execution is enabled.

Existing positive verification test now explicitly sets `AURELIUS_ALLOW_SKILL_EXEC=1`, because executable verification is no longer ambient/default behavior.
