## Problem Statement
Verify that archive extraction rejects symlink-based escape paths (absolute outside targets, relative traversal, member-path traversal, and write-through via pre-existing destination symlinks), and confirm production code does not bypass `safe_archive`.

### Modified

## Reproduction Result
**Not reproduced; regression-locked.**

All new adversarial tests passed on first run against the current implementation. No production patch was applied (per runbook: do not invent fixes when the door is already locked).

Existing protections confirmed in `SafeTarExtractor.extract()`:
- Rejects member names containing `..` path components
- Resolves symlink targets relative to member parent and rejects link targets outside `dest_dir`
- Uses `.resolve()` containment checks before writing files (blocks write-through via pre-existing destination symlinks)

Existing protections confirmed in `SafeZipExtractor.extract()`:
- Rejects `..` path components and paths resolving outside `dest_dir`
- `.resolve()` containment check blocks write-through via pre-existing destination symlink directories
