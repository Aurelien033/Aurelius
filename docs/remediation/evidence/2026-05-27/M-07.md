# Evidence Manifest — M-07: Rust api-gateway JWT_SECRET expect panic

## Row Metadata
- **Row ID**: M-07
- **Status**: PARTIAL (deferred — Rust owner)

## Problem
`crates/api-gateway/src/config.rs:32` calls `.expect("JWT_SECRET must be set")` which panics the binary if the env var is unset. At runtime this causes crash-on-start rather than a graceful error.

## Decision: DEFERRED
Fixing this requires:
1. Rust toolchain (cargo build)
2. Rewriting to return `Result<Config, Error>` and propagate gracefully
3. Validation that the change compiles

These are legitimate but outside the Python/BFF remediation lane. The Rust crate has its own ownership and the fix should be coordinated with the Rust maintainer.

## Recommended Fix (for Rust owner)
Replace: `jwt_secret: env::var("JWT_SECRET").expect("JWT_SECRET must be set")`
With: `jwt_secret: env::var("JWT_SECRET").map_err(|e| { log::error!("JWT_SECRET not set: {}"; e); ConfigError::MissingEnv("JWT_SECRET") })?`

And change the binary entrypoint to handle `Result<Config, _>` gracefully (log + exit 1, not panic).

No changes made (deferred for Rust owner).
